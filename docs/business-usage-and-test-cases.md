# 业务使用说明与测试案例

**读者：** 业务同事、带测的产品/运营、代跑的 WorkBuddy  
**更新：** 2026-08-09  
**适用仓库：** Private 生产仓（Public 只是安装壳，本身没有生产能力）  
**每种方式 1 个完整例子：** 见 **§1.5**（案例 A～G，可照抄对话）

---

## 0. 现在能做什么 / 不能做什么

| 你想做的事 | 是否开放 | 业务怎么选 |
|------------|----------|------------|
| 出一份**店员商品培训可编辑 PPT** | ✅ 默认主路径 | 「构件化商品培训 PPT」 |
| 出一份**商品讲解完整视频 MP4** | ✅ 路线开放，电脑环境要齐 | 「商品培训视频」+ 授权包装图 |
| 绿色五页旧 PPT（金银花露那套壳） | ❌ **已下线** | 不要选；请改用构件化 PPT |
| 疾病/健康科普视频（如风热证） | ❌ 暂未业务自助 | 仅可看金样；正式自助另专项 |

**原则（三条红线）：**

1. 医学/功效/剂量只来自**你们审核过的稿**，系统不替你编。  
2. **没确认初稿，不出正式成品。**  
3. **没公司授权的包装图，不伪造包装**（PPT 用占位槽；正式视频必须授权图）。

## 1. 业务怎么用（推荐：WorkBuddy 对话）

业务**不必**自己敲命令。在 WorkBuddy 里按下面说即可。

### 1.1 第一次：安装 / 更新（仅需有权限的人做一次）

对 WorkBuddy 说（或按公司下发的安装句）：

> 请安装/更新连锁药店培训内容工厂（Private 生产仓），装完后打开业务引导页。

装好后本机应能打开业务门户（模板货架）。若提示「不是 Private 生产仓 / 无权限」，找管理员开 GitHub 权限，不要用未授权镜像。

### 1.2 日常：出商品培训 PPT（主路径）

对 WorkBuddy 说：

> 我要做**构件化商品培训 PPT**。  
> 商品名是【×××】。  
> 培训要点如下：  
> 1. ……  
> 2. ……  
> 3. ……  
> 请先出**内容初稿和缺口清单**给我确认，**确认前不要生成正式 PPT**。

系统应：

1. 创建任务并生成**内容初稿**（你能看懂的 Markdown）+ **缺口清单**  
2. 等你说「内容确认 / 可以生成」  
3. 再生成 **可编辑 PPTX**  
4. 告诉你取件位置（业务包里的「05_交付物放这里」）

你确认时建议这样说：

> 初稿我看过了，以当前内容为准，**批准内容**，请生成正式 PPT。确认人：【你的姓名】。

取件后：用 WPS / Office 打开 `终稿.pptx`，检查页数、文字是否可改、有没有别的商品字样。

### 1.3 日常：出商品完整培训视频（可选）

前提：本机视频环境已就绪（旁白 TTS + 渲染包 + ffmpeg）。不确定时让 WorkBuddy 先查：

> 请检查本机商品完整视频环境是否就绪（video_full）。

若就绪，再说：

> 我要做**商品培训完整 MP4**。  
> 商品名是【×××】。  
> 授权包装图路径是【本机图片路径】。  
> 旁白/分段要点是：……  
> 请先出脚本初稿，我确认内容后再确认包装图，最后再渲染正式视频。

正式视频需要两道确认：**内容** + **授权包装图**（带凭证说明）。

### 1.4 工程师代跑时的等价命令（业务可不看）

```bash
# 默认 PPT
python3 scripts/business_job.py new --route product-pptx-component-v1 \
  --theme "商品名" --notes $'要点1\n要点2\n要点3' --auto-draft
python3 scripts/business_job.py approve --job <任务ID> --gate content --by "姓名"
python3 scripts/business_job.py render --job <任务ID>
python3 scripts/business_job.py open --job <任务ID>

# 商品 MP4（环境齐时）
python3 scripts/business_job.py new --route product-mp4-full-v1 \
  --theme "商品名" --notes "…" --product-image "/路径/包装图.png" --auto-draft
python3 scripts/business_job.py approve --job <任务ID> --gate content --by "姓名"
python3 scripts/business_job.py approve --job <任务ID> --gate product_image \
  --by "姓名" --authorization-reference "凭证编号或说明"
python3 scripts/business_job.py render --job <任务ID>
```

状态查询：`python3 scripts/business_job.py status --job <任务ID>`

### 案例 A · 构件 PPT（商品名 + 几条要点）— **默认、最常用**

**场景：** 店员内部商品培训，只要可编辑 PPT；审核要点还不全，先出结构再补。

**你对 WorkBuddy 说（第 1 轮）：**

```text
我要做构件化商品培训 PPT。
商品名是：舒心维C咀嚼片（演练）。
培训要点：
1. 补充维生素C，适合日常饮食不均衡人群（待药师口径确认）
2. 咀嚼方便，门店主推话术强调依从性（待确认）
3. 联合推荐可搭配基础营养品，不硬凑处方药（待确认）
请先出内容初稿和缺口清单，确认前不要生成正式 PPT。
```

**你应看到：**

- 任务已创建（有任务 ID）  
- 有一份可读的 **内容初稿**（封面名是「舒心维C咀嚼片（演练）」）  
- 有 **缺口清单**（规格、审核功效、联合场景等可能仍待确认）  
- **还没有** 正式 `终稿.pptx`

**你对 WorkBuddy 说（第 2 轮 · 确认后）：**

```text
初稿我看过了。待确认字段先按当前稿出一版内部讨论用。
批准内容，确认人：张三。请生成正式 PPT 并打开取件目录。
```

**你应拿到：**

- 路径类似：`…/05_交付物放这里/<任务ID>/`  
- 文件：`终稿.pptx`、`交付说明.md`、内容确认记录等  
- 用 WPS/Office 打开：文字可改；全文应是演练商品名，**不应**串成金银花露等其他金样

**对应测试：** TC-PPT-02 + TC-PPT-04 + TC-PPT-05

### 案例 B · 构件 PPT（完整审核脚本）

**场景：** 药师/合规已给结构化审核稿，希望尽量锁定文案再出 PPT。

**准备：** 本机有一份 `script.structured.json`（或 Word 已由支持转成该格式）。演练可让工程师用金样脚本改商品名后给你路径。

**你对 WorkBuddy 说：**

```text
我要做构件化商品培训 PPT。
商品名以脚本里的为准。
完整脚本路径：/Users/某同事/桌面/舒心维C_script.structured.json
请按脚本出内容初稿供我确认；确认前不要生成正式 PPT。
```

**确认后：**

```text
脚本内容确认，确认人：李四。请生成正式 PPT。
```

**你应看到：**

- 初稿中的功效/联合/注意与脚本一致，系统**没有**另编未出现在脚本里的功效  
- 正式 PPT 页结构按构件 recipe 展开（通常多页：封面、痛点/功效、特点、人群、联合、总结、注意等）  
- 若脚本某条标了 hidden / 不说大品牌，正式稿里也不应出现

**对应测试：** TC-PPT-04 + TC-NEG-03（防扩写）

### 案例 C · 门户选模板 + 复制口令

**场景：** 不习惯长对话，先在网页货架点选再粘贴给 WorkBuddy。

**步骤：**

1. 打开业务引导页（安装后的模板货架）。  
2. 点选 **「构件化商品培训 PPT（默认主路径）」**（不要点已下线的绿色单品）。  
3. 点 **「选用 · 复制任务口令」**。  
4. 回到 WorkBuddy，粘贴口令，把里面的【商品名】【要点】改成真实内容。  

**口令改完示例：**

```text
我选【构件化商品培训 PPT（默认主路径）】，需要可编辑 PPTX。
商品名是【舒心维C咀嚼片（演练）】，审核要点是【补充维C；咀嚼方便；联合需审核】。
请先整理内容初稿和缺口供我确认；确认后再生成正式成品。
```

**之后**与案例 A 第 2 轮相同：确认 → 生成 → 取件。

**对应测试：** TC-PPT-01

### 案例 D · 商品培训完整 MP4

**场景：** 要可播放的店员培训视频（不是 PPT）；本机视频环境已就绪。

**第 0 步 · 先查环境：**

```text
请检查本机商品完整视频环境是否就绪（video_full）。
```

- 若提示缺 TTS / kit / ffmpeg：**整例暂停**，标「阻塞·环境」，不要硬要正式片。  
- 若提示就绪：继续。

**第 1 步 · 建任务（你说）：**

```text
我要做商品培训完整 MP4。
商品名：舒心维C咀嚼片（演练）。
授权包装图：/Users/某同事/授权素材/舒心维C_包装正面.png
分段要点（可先简版）：
1. 为什么要了解：门店要说清定位与边界
2. 商品基础信息：规格文号以公司资料为准
3. 核心讲解：补充维C（待审核稿）
4. 核心功效：……
5. 产品特点：……
6. 适宜人群：……
7. 联合用药：有几条写几条
8. 总结：记住定位与话术红线
请先出脚本初稿，确认前不要渲染正式视频。
```

**第 2 步 · 批内容：**

```text
脚本初稿确认，确认人：王五。
```

**第 3 步 · 批包装图：**

```text
包装图是公司授权原图，确认人：王五，授权凭证：内宣-2026-演练-001。请绑定后渲染正式 MP4。
```

**你应拿到：**

- `05_交付物放这里/<任务ID>/终稿.mp4` 可播放  
- 有确认记录；**没有**授权图时不应出正式片（可单独用案例测一次）

**对应测试：** TC-MP4-01～03

### 案例 E · 工程师 / 支持用命令行代跑 PPT

**场景：** 业务把商品名和要点发群里，支持同事本机代跑（业务自己可不看命令）。

```bash
# 1) 创建并出草稿
python3 scripts/business_job.py new \
  --route product-pptx-component-v1 \
  --theme "舒心维C咀嚼片（演练）" \
  --notes $'补充维生素C（待确认）\n咀嚼方便（待确认）\n联合需审核（待确认）' \
  --job-id "biz-demo-ppt-shuxin-vc" \
  --auto-draft

# 2) 业务口头确认后，支持代批
python3 scripts/business_job.py approve \
  --job biz-demo-ppt-shuxin-vc \
  --gate content \
  --by "张三"

# 3) 生成并打开取件
python3 scripts/business_job.py render --job biz-demo-ppt-shuxin-vc
python3 scripts/business_job.py open --job biz-demo-ppt-shuxin-vc --reveal
```

**期望：** 与案例 A 相同交付物；`status` 显示 `delivered`。

## 2. 测试案例怎么用

- **测试人：** 业务或运营；旁观记录：产品/工程师  
- **环境：** 已装好 Private 生产仓的电脑；优先用 **真实商品名 + 真实审核要点**（可用脱敏样例，但不要用「金银花露」当新主题去测残留）  
- **记录：** 每个案例勾「通过 / 失败 / 阻塞」，失败写一句现象即可  
- **总通过标准：** 主路径案例 **TC-PPT-01～05** 全部通过，才算「业务能自助出 PPT」

建议测试商品命名：用你们真实在推的单品，或「测试商品-业务验收-日期」，**不要**直接用金样商品名复制粘贴当新主题。

## 3. 测试案例清单

### A. 商品培训 PPT（必须测）

#### TC-PPT-01 · 选对课型

| 项 | 内容 |
|----|------|
| **目的** | 业务能找到正确入口，不会走已下线绿色壳 |
| **步骤** | 1）打开业务门户或对 WorkBuddy 说「我要做商品培训 PPT」2）看推荐/可选课型 |
| **期望** | 出现「构件化商品培训 PPT」或等价表述；**不**把绿色五页当作推荐主路径；若看到绿色，应标明已下线/仅金样 |
| **通过** | □ |

#### TC-PPT-02 · 只交商品名 + 几条要点就能出初稿

| 项 | 内容 |
|----|------|
| **目的** | 资料不齐也能先出结构，不要求一次填完美 |
| **步骤** | 1）商品名：自定 2）要点至少 3 条（卖点/人群/注意等任意）3）要求「先初稿、先别出正式 PPT」 |
| **期望** | 得到可阅读的内容初稿 + 缺口清单；任务状态类似「等待内容确认」；**交付区没有**正式 `终稿.pptx` |
| **通过** | □ |

#### TC-PPT-03 · 未确认不能出正式稿

| 项 | 内容 |
|----|------|
| **目的** | 审批闸门有效 |
| **步骤** | 在 TC-PPT-02 的任务上，**不说确认**，直接要求「马上生成 PPT」 |
| **期望** | 被拒绝或提示需先内容确认；`05_交付物放这里` **不出现**该任务正式交付 |
| **通过** | □ |

#### TC-PPT-04 · 确认后生成可编辑 PPT 并取件

| 项 | 内容 |
|----|------|
| **目的** | 主路径跑通 |
| **步骤** | 1）确认初稿 2）生成正式 PPT 3）打开取件目录 |
| **期望** | 有 `终稿.pptx`（可用 WPS/Office 打开、文字可编辑）；有交付说明；目录里**没有**源码、`node_modules`、一堆日志垃圾 |
| **通过** | □ |

#### TC-PPT-05 · 内容是自己的，没有串货

| 项 | 内容 |
|----|------|
| **目的** | 不把金样商品文案带进新主题 |
| **步骤** | 打开 `终稿.pptx`，全文搜索（或肉眼翻页） |
| **期望** | 封面/正文商品名是你填的；**不应出现**无关金样商品名（如误串的金银花露、福尔麦金利等，除非你主题本身就是该商品）；标「待确认」的字段你知情 |
| **通过** | □ |

#### TC-PPT-06 · 修改要点后重出（可选）

| 项 | 内容 |
|----|------|
| **目的** | 改内容要重新审，不能偷用旧批准 |
| **步骤** | 1）改 notes / 脚本 2）重新 draft 3）不重新批准就要求 render；或重新批准后再 render |
| **期望** | 内容变更后旧批准失效，需重新确认；重新批准后新 PPT 反映新文案 |
| **通过** | □ |

#### TC-PPT-07 · 缺图不瞎补包装（可选）

| 项 | 内容 |
|----|------|
| **目的** | 无授权包装不伪造 |
| **步骤** | 故意不提供包装图，完成 PPT 生成 |
| **期望** | 图位为占位/「待业务授权」类提示，**不是**随便一张假包装 |
| **通过** | □ |

## 5. 常见问题（业务向）

**Q：初稿里很多「待确认」正常吗？**  
正常。表示还没写入审核结论；你补齐并确认后再生正式稿。

**Q：可以只在 PPT 里大改字交差吗？**  
小改版式可以；**大改功效/话术**请回到任务改内容并重新确认，避免下次生成又覆盖、也避免无审稿。

**Q：取件在哪？**  
业务资料包目录下的 **`05_交付物放这里/<任务ID>/`**。WorkBuddy 可以说「打开取件目录」。

**Q：失败了怎么办？**  
任务会停在「环境不足 / 质检失败」等状态，**不会**假装已交付。把任务 ID 和屏幕提示转给支持同学即可。

**Q：绿色旧模板还能用吗？**  
不能再走业务自助。新主题一律用**构件化商品培训 PPT**。
