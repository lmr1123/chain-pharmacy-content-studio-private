# 网页版药店动画课件与视频工作室方案

## 1. 结论

可以，而且网页版是更适合的产品形态。

但不建议从零复制一个覆盖所有行业的 Vyond 或万彩动画大师，而应做成一个聚焦药店内部培训的“垂直版 Vyond”：

> 输入内部审核脚本，AI 自动生成可编辑的场景式动画初稿；内容人员在网页中调整人物、商品图、文字、动画和配音；同一项目可演示、导出 PDF/PPTX，也可渲染为 MP4 视频。

首期目标不是提供无限自由的专业动画软件，而是用 12–18 种高频场景模板覆盖健康科普和商品培训的大多数内容。

## 2. 对标产品应学习什么

### Vyond Go

应该学习：

- 从脚本、文档、PPTX 或提示词生成视频初稿；
- 模板控制画面风格；
- 生成后仍可继续编辑；
- Quick Edit 与高级 Studio 两级编辑体验；
- 动画人物、AI Avatar、旁白和混合媒体组合。

不需要首期复制：

- 面向所有行业的庞大素材商城；
- 复杂双人剧情和多人对话；
- 大量通用商业模板；
- 95 种语言等全球化能力。

### 万彩动画大师 / Animiz

应该学习：

- 场景列表 + 中央画布 + 属性面板 + 时间轴；
- 进场、强调、退场动画预设；
- 动画角色、矢量图、图表和商品图；
- PPTX 导入、TTS、字幕和视频导出；
- AI 生成工程后可以二次修改。

不需要首期复制：

- 无限画布与复杂镜头缩放；
- 完整桌面动画软件的所有轨道能力；
- 大量与药店培训无关的特效。

## 3. 统一产品模型

系统不把“PPT”和“视频”做成两套编辑器，而是使用统一的“场景项目”：

```text
项目
 ├─ 场景 1
 │   ├─ 背景
 │   ├─ 标题
 │   ├─ 商品图/医学插图
 │   ├─ 动画角色或数字人
 │   ├─ 旁白与字幕
 │   └─ 进场/强调/退场动画
 ├─ 场景 2
 └─ 场景 3...
```

每个场景既是一页演示稿，也是一段视频镜头。

同一份场景数据可以：

- 在网页中直接播放为动画演示；
- 截取每个场景的静态状态导出 PDF；
- 映射为可编辑 PPTX；
- 按时间轴渲染为 MP4；
- 输出字幕 SRT 和音频。

## 4. 网页编辑器形态

### 快速编辑模式

适合总部内容人员处理批量任务：

- 左侧：场景缩略图；
- 中间：16:9 画布与即时预览；
- 右侧：文字、图片、人物、配音、动画和模板属性；
- 顶部：AI 生成、预览、批量套用、导出；
- 无需接触复杂关键帧。

可以完成：

- 更换场景模板；
- 替换商品图、人物和医学插图；
- 调整屏显短句；
- 修改读音、停顿、语速；
- 切换进场、强调和退场动画；
- 单场景重新生成。

### 高级编辑模式

仅给需要精修的人员使用：

- 多轨时间轴；
- 元素起止时间；
- 图层顺序；
- 关键帧与缓动；
- 转场；
- 音频波形和字幕时间；
- 数字人片段裁切。

首期高级模式只支持常用能力，不建设完整 Adobe After Effects。

## 5. AI 自动创作工作流

```text
审核脚本
  → 结构识别
  → 场景切分
  → 场景类型选择
  → 屏显短句提取
  → 素材检索/生成
  → 动画与节奏建议
  → TTS 配音
  → 字幕时间轴
  → 数字人片段
  → 可编辑初稿
  → 人工精修
  → 批量导出
```

AI 的职责是“导演和排版”，不是修改药学结论。

已审核旁白作为锁定字段保存。AI 可以生成：

- 场景切分；
- 屏显短句；
- 画面关键词；
- 场景模板建议；
- 素材匹配；
- 动画节奏；
- 数字人出现位置。

任何对锁定正文的修改都必须生成差异版本，不能静默覆盖。

## 6. 高价值动画效果如何实现

画面质量主要来自模板组件和素材体系，而不是每次用生成式视频模型随机生成。

建议首期建设以下场景组件：

1. 栏目片头；
2. 章节导航；
3. 数字人/卡通药师讲解；
4. 三点知识卡；
5. 症状或适用场景卡；
6. 人体部位示意；
7. 作用过程或机制流程；
8. 商品包装主视觉；
9. 商品特点卡；
10. 适宜人群；
11. 用法步骤；
12. 注意事项/禁忌；
13. 正误对比；
14. 门店沟通场景；
15. 时间线；
16. 图表；
17. 本章总结；
18. 片尾。

每个组件配置：

- 2–4 套版式；
- 3–6 个动画预设；
- 字数上限与自动缩排规则；
- 可用人物姿势；
- 可用素材类型；
- 适合的旁白时长。

这样能在保持品牌一致性的同时，避免每条视频看起来完全一样。

## 7. 数字人方案

数字人应作为场景中的一个元素，而不是让数字人从头到尾占据全片。

推荐比例：

- 20%–30%：数字人或卡通药师负责开场、章节衔接和总结；
- 70%–80%：信息卡、医学示意、商品图和动画流程。

这样比全程“一个人站着念稿”更生动，也能显著降低数字人渲染成本和视觉疲劳。

### 真人数字人

零采购的开源 PoC 可优先测试：

- MuseTalk 1.5：负责音频驱动嘴型；
- 准备经过授权的真人基础视频或人物形象；
- CosyVoice：生成中文旁白；
- FFmpeg：抠像、合成和转码。

MuseTalk 官方说明代码为 MIT，模型允许商业使用，但仍需逐项核对依赖许可证，并取得真人肖像和声音授权。

### 卡通药师

更适合参考样片的做法：

- 为固定卡通药师准备 6–10 个姿势；
- 准备眨眼、嘴型、指向、拿扩音器、强调等动作；
- 使用 SVG/Lottie/序列帧或骨骼动画；
- 根据字幕和音素触发口型。

卡通角色比单张照片数字人更稳定、更有品牌辨识度，也更适合大批量科普和商品培训。

### 不建议

- Wav2Lip 作为生产依赖：官方许可存在非商业限制；
- 每个镜头都用文生视频：画风、商品包装和人体结构难以保持一致；
- 未经授权克隆内部药师肖像或声音。

## 8. 推荐的开源技术底座

目前没有一个成熟开源项目可以直接同时提供 Vyond Go 式 AI 编排、Animiz 式在线动画编辑、数字人、批量生成以及 PDF/PPTX/MP4 全格式导出。可行路线是用成熟开源组件组成垂直工作室，而不是寻找一个可以直接改名上线的完整项目。

### 主方案：完全可控的自建 Web 工作室

- Web：Next.js / React；
- 场景与时间轴数据：自定义 Scene JSON；
- 画布预览：PixiJS 或 Canvas/SVG；
- 视频动画与无头渲染：Revideo（MIT）；
- 最终编码：FFmpeg；
- 可编辑 PPTX：PptxGenJS（MIT）；
- PDF：浏览器打印或场景快照合成；
- 中文 TTS：CosyVoice，保留替换其他 TTS 的接口；
- 数字人：MuseTalk 作为首个 PoC；
- 队列：BullMQ + Redis；
- 数据：PostgreSQL；
- 素材存储：MinIO 或企业文件服务器。

选择 Revideo 的原因：

- MIT，可以用于企业内部系统；
- 同一项目支持浏览器 Player 和服务器无头渲染；
- 支持动态输入、音频和帧级同步；
- 比直接使用 FFmpeg 编写动画更容易维护。

风险：

- Revideo 的成熟度低于 Remotion；
- 网页编辑器、模板系统和素材库仍需自行开发；
- 必须通过 60 秒样片 PoC 验证中文字体、长视频和批量渲染。

### 成熟度备选：Remotion

Remotion 的生态、文档、浏览器预览和批量渲染更成熟，最适合作为生产引擎；但大型盈利公司需要 Company License，因此在“当前无采购”约束下不作为默认方案。

### 可参考但不直接作为核心

- OpenVideo/react-video-editor：具有画布、时间轴和浏览器导出，可用于参考交互，但企业超过 3 人需要公司许可；
- VideoFlow：JSON、浏览器/服务端渲染和 React 编辑器理念与本项目接近，但项目较新，适合作架构参考，不建议未经 PoC 直接作为核心；
- Motion Canvas：动画能力强，但面向程序化动画创作，不是完整批量编辑工作台；
- MoviePy：适合拼接和小工具，不适合维护丰富动画模板。

## 9. PDF、PPTX 和视频的效果边界

### MP4

- 完整保留动画、数字人、旁白、字幕和转场；
- 是高价值培训视频的主交付格式。

### 网页演示

- 完整保留场景动画；
- 可以像 PPT 一样上一页/下一页播放；
- 后续可加入讲者模式。

### PDF

- 每个场景导出一个代表性静态画面；
- 不包含动画和数字人播放；
- 适合归档与打印。

### PPTX

- 标题、文字、图片、形状和图表保持可编辑；
- MVP 默认输出静态、可编辑的原生对象；
- PptxGenJS 没有稳定的对象级 PowerPoint 动画能力，首期不承诺自动还原原生动画；
- 复杂网页动画、数字人和特效无法无损转换成 PowerPoint 原生动画。

如果要求 PPTX 中完全保留视频效果，有两种选择：

1. 将每个动画场景渲染为视频并嵌入 PPTX；
2. 输出静态可编辑 PPTX，同时附完整 MP4。

推荐默认采用第二种。

## 10. 对参考样片的预期效果

参考视频约 3 分钟、1080p、30fps，主体是二维卡片、图片、字幕、角色和简单转场，不属于复杂三维动画。

在完成对应模板和素材后，可以稳定达到或超过其制作完成度：

- 统一品牌包装：可稳定复现；
- 章节、标题和信息卡：可完全模板化；
- 商品图和医学插图：可自动套版；
- 字幕与配音：可自动同步；
- 卡通角色：通过动作资产稳定复用；
- 数字人讲解：可插入指定场景；
- 复杂独特插画：仍需要素材生成或人工选择。

合理目标是：

- 80%–90% 的场景自动完成；
- 10%–20% 的场景进行素材替换或局部排版；
- 不追求每条视频都随机生成全新视觉，而追求高质量、统一和可返修。

## 11. 验收标准

### 内容

- 审核旁白逐字一致；
- 每个段落保留内容 ID 和原文哈希；
- AI 生成的屏显短句与审核正文分开保存。

### 编辑

- 场景、人物、商品图和动画可在网页中修改；
- 单个场景可以重新生成，不重做整条视频；
- 修改旁白后，字幕和时长能重新计算。

### 画面

- 1920×1080、30fps；
- 中文无溢出、截断和字体替换；
- 商品图不拉伸；
- 片头、字幕、色板和 Logo 一致；
- 至少 12 类场景组件。

### 数字人

- 普通话口型基本同步；
- 人脸无明显闪烁和结构变形；
- 1080p 合成后边缘可接受；
- 长旁白按段生成，失败可单段重试。

### 批量

- 一次导入 20 条脚本；
- 合法输入的任务成功率不低于 95%；
- 失败任务不影响整批；
- MP4、PDF、PPTX 和字幕可按任务打包导出。

## 12. 建议实施顺序

### 方案验证 PoC

只做一条 60–90 秒金标准样片：

- 4–6 个场景；
- 3 种信息卡；
- 1 个卡通药师；
- 1 段真人数字人；
- 中文 TTS 和逐句字幕；
- 网页可编辑；
- 导出 MP4、PDF、PPTX。

PoC 只回答四个问题：

1. 开源渲染引擎能否达到参考样片效果；
2. 数字人质量是否可接受；
3. 三种导出格式能否满足业务使用；
4. AI 自动编排后需要多少人工返修。

### MVP

PoC 通过后再开发：

- 网页快速编辑器；
- 12–18 类场景组件；
- 素材库和模板库；
- 脚本批量导入；
- AI 场景编排；
- 批量预览与渲染；
- 多格式导出。

### 后续增强

- 高级时间轴；
- 更多角色动作；
- 数字人形象管理；
- 企业品牌模板编辑器；
- 互动网页课件；
- 更多画幅。

## 13. 最终推荐

在“不采购现成 SaaS、希望用 AI 搭建”的前提下，推荐：

> 自建场景式 Web 编辑器 + Scene JSON + Revideo + FFmpeg + PptxGenJS + CosyVoice + MuseTalk。

采用 Vyond Go 的“AI 生成可编辑初稿”产品逻辑，采用万彩的“场景、画布、时间轴、动画素材”编辑逻辑，但只建设药店培训需要的高频场景。

不要先建设通用动画平台。先用一条金标准样片证明画面、编辑、数字人和多格式导出，再决定是否扩展为完整工作室。
