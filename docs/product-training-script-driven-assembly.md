# 商品培训脚本驱动的自由组装方案

## 结论

业务不应选择一套固定页序模板，也不应每次重新定制视频。正确的复用单位是：

1. 一个锁定的 `style_pack_id`；
2. 一组可按内容意图选择的 `scene_recipe_id`；
3. 场景内部可替换的组件与动效；
4. 按主题连续积累的 `series_id + role_ids` 素材。

因此，固定的是视觉语言和质量门禁，不是每个主题的章节数量、页面顺序或素材内容。

## 业务实际操作

1. 下载业务填写 Word，复制一份并替换示例内容。
2. 保留需要的栏目，删除不需要的栏目；章节顺序可以按课程逻辑调整。
3. 只粘贴药师和合规法务已经审核的原文。
4. 另行上传授权商品包装、Logo、说明书、检测资料和证据图片。
5. 系统输出自动分镜、素材缺口和低置信度章节；业务只确认异常项。
6. 业务可对单个章节更换推荐场景，不需要从头定制整条视频。
7. 预览通过后统一导出 MP4、PPTX 或 PDF。

业务不需要填写组件 ID、时码、坐标、提示词或动画参数。

## 四层复用模型

### 1. 风格包

每个项目只允许一个主风格包。本商品系列绑定
`style-pack.reference-product-blue-v1`，统一控制：

- 蓝色母版、栏目签、内部培训声明；
- 字体、字号层级、字幕和强调色；
- 数字人身份、比例、口型和站位；
- 卡片圆角、描边、阴影、间距；
- 进入、停留、强调和退场节奏；
- 可使用的图片子风格白名单。

### 2. 场景配方

场景配方是“内容意图 → 画面结构”的映射。业务脚本可以自由省略、重复和重排：

| 内容意图 | 可选场景配方 |
| --- | --- |
| 需求教育、问题引入 | 办公/生活问题故事、主体标注、反向量表 |
| 症状或常见问题 | 三项症状图板、人物讲解、分项退出 |
| 作用机制 | 中心关系图、节点顺序进入 |
| 商品亮相 | 授权包装主视觉、旋转光束 |
| 商品总览 | 包装、品牌、1–4 个卖点标签 |
| 核心功效 | 每镜 1–3 张证据图累积 |
| 产品特点 | 工艺/原料/资料证据与放大镜 |
| 适宜人群 | 每镜 1–3 类人群序列 |
| 联合方案 | 每镜 1–2 组授权包装与审核话术 |
| 总结 | 按条数自动选择总结矩阵 |

超过配方容量时使用同配方续镜，不缩小字号；缺少某章节时直接跳过。

### 3. 组件与动效

组件只暴露经过验证的内容槽位，例如标题、图片、条目、标签、站位和时长。动效只控制入场、循环、强调和退场。系统禁止无约束随机拼接：

- 每镜只有一个主要运动焦点；
- 同一角色只能使用同一身份和动作语法；
- 组件和动效必须兼容当前风格包；
- 真实包装和证据必须来自授权资产；
- 未通过用户确认的候选组件不能默认进入批量生产。

### 4. 同主题素材系列

素材不能按视频孤立生成。每个系列绑定：

- `series_id`：稳定系列身份；
- `role_ids`：症状人物、机制主体、人群、环境、商品、证据等角色；
- 固定色板、材质、构图安全区和提示词变量；
- 动画契约，例如摇摆、呼吸、吐气、疼痛脉冲；
- 每个成员独立的来源、技术、视觉和医学审核状态。

新主题先查已有系列。已有系列能表达时只补成员；无法表达时先签一张代表图，再建立新系列。这样不同主题内容可以变化，但画风不会“七拼八凑”。

## 自动规划规则

`scripts/plan_training_course.py` 支持 `.txt`、`.md` 和 `.docx`：

1. 保留脚本章节顺序和原文；
2. 用章节标题识别内容意图；
3. 只从当前风格包筛选场景配方；
4. 输出组件、动效、素材角色与约束；
5. 无法识别的章节进入 `unresolved_sections`，不猜测医学含义；
6. 缺失授权素材进入 `asset_gap_tasks`；
7. 在业务确认异常项后才进入配音、字幕和渲染。

## 当前边界

- 现有商品培训组件已达到技术 QA，但尚未全部获得用户视觉确认，不能直接标记为批量生产完成。
- Word 样本用于说明业务输入方式；其中辅酶 Q10 内容是具体填写示例，不自动等同于公司已审核生产文案。
- 真正业务生产仍需公司提供授权包装、Logo、说明书、检测资料和最终审核脚本。
