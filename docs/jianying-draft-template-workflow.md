# 视频生成到剪映精修与模板沉淀流程

更新日期：2026-07-31  
状态：剪映保留为有限用途精修路径；Revideo 业务编辑器进入使用观察期

## 固定生产路径

> 审核内容＋结构化模板配置 → Revideo／素材生成 → VectCutAPI 生成剪映多轨草稿 → 剪映微调 → 保存剪映草稿模板版本 → 审核可复用改动 → 回填并发布正式结构化模板新版本

## 当前分流

生成后根据实际需求选择：

1. **改模板内部文字、插图和基础布局**：在 Revideo 原编辑器的业务图层插件中调整，然后直接“导出视频”或“导出可编辑课件”；不要求保存模板。
2. **改单条视频节奏、字幕、音频、裁切、转场和后加效果**：进入剪映精修。
3. **后续项目还要复用当前调整**：在 Revideo 中使用“另存为新模板版本”，或将剪映里已确认可复用的改动人工回填为结构化模板新版本。

两条编辑路径都不得自动覆盖 settled 正式模板。

## 每层职责

1. **审核内容**：只使用当次已审核脚本和已授权素材；未提供内容不得自动补写。
2. **结构化模板**：保存 `template_id`、唯一 `style_pack_id`、场景配方、组件槽位、素材引用、布局、动画和音频规则，是批量生成的唯一源数据。
3. **Revideo／素材生成**：负责数字人口型、粒子、电流、程序动画和高保真成片；完整解码、黑场、帧数、音频和关键帧 QA 在这一层完成。
4. **VectCutAPI**：把正式成片按场景切成命名片段，并加入独立旁白和原生字幕，生成自包含剪映草稿。此步骤不会自动把片段内部元素还原成剪映原生图层。
5. **剪映微调**：用于单条视频的裁切、重排、转场、字幕、音频及剪映原生效果调整。
6. **版本沉淀**：剪映保存产生剪映草稿版本，不自动改变正式模板。只有经过确认、能复用于后续项目的改动，才映射回结构化配置并发布正式模板新版本。

## 版本规则

- 正式结构化模板：`template.<name>@<version>`，用于批量生成。
- 剪映草稿模板：`template.<name>@<version>-jianying`，用于人工精修和复用。
- 当前项目临时修改不得静默覆盖任一正式版本。
- 晋升记录必须写明修改项、影响范围、验证证据和回滚目标。
- 无法可靠反向映射的剪映特效只保留在剪映版本，不冒充结构化模板能力。

- 完整解码通过，未检出黑场；

## 可编辑边界

本次完整金样以保真优先：

- 剪映原生可编辑：七段场景片段的重排、裁切、拆分、替换和变换；完整旁白；逐条字幕；后加剪映转场、关键帧和效果。
- 保留在 Revideo 片段内部：数字人口型与骨架、场景内部图文层、粒子／电流、程序动画。

若未来要求“场景内部每张插图和文字都成为剪映原生对象”，需要为对应场景新增专用 VectCut 装配器，并重新完成与金样的视觉一致性验收；不能把保真视频片段描述为完全分层可编辑。

本次结论：该剪映交付仅保留作成片分段精修通道，不作为业务可编辑模板方案。

## 使用观察期

自 2026-07-31 起，Revideo 业务编辑器和剪映精修分流方案先进入真实使用观察，不继续预先扩展功能。只有当同一问题在多次业务任务中重复出现，并明显影响完成调整或导出时，才进入下一轮迭代。业务操作说明见 `docs/revideo-business-editor-usage.md`。
